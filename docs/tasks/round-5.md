# 第五轮任务卡：先整合，再扩展

更新日期：2026-11-04。基线：`main@801953d`（#111）。

本页在第四轮任务卡（[README](README.md)）的基础上，加入 2026-11-04 独立评审的结论，
并重新安排分派顺序。第四轮的通用规则 G1–G15 继续有效；本页追加 G16–G19。
交给 agent 时，同时提供 [README](README.md)（G1–G15）、本页（G16–G19 与分工）和对应卡片。

## 评审结论摘要

2026-11-04 的评审把 PyRPMD 与 i-PI 3.3.1、LAMMPS `fix pimd/langevin`、NQCDynamics.jl、
SHARC 4.0、Newton-X 26、TorchSim、FeNNol、Tinker-HP、infretis、RPMDrate 和 Caracal 做了比较，
并在同一台机器上实测了与 i-PI 的单线程吞吐量（P=32，PILE-L，谐振势，每秒步数，已扣除启动时间）：

| 原子数 | PyRPMD 原生内置势 | PyRPMD Python 势 | i-PI 3.3.1 `ffdirect` |
| --- | --- | --- | --- |
| 3 | 38,700 | 1,234 | 333 |
| 64 | 2,000 | 636 | 338 |
| 512 | 212 | 109 | 97 |
| 4096 | 19.5 | 12.0 | 18.1 |

结论：

- 气相 RPMD 速率、checkpoint 与来源追溯已经领先同类程序；小体系原生路径约为 i-PI 的 115 倍。
- 差距不在“缺少某个方法名”，而在四个方面：传播核心分裂（约 25 个 `*Dynamics` 类、三套 PIMD 引擎）、
  凝聚相性能（带热浴时大体系优势消失）、生态接入（i-PI `extras`、PLUMED、RPMDrate 输入）、
  可信度（旗舰算例尚未达到发表级收敛、未发布到 PyPI）。
- 第四轮退回或拒绝了十余个分支。代码增长速度已经超过审查与验证能力。

因此本轮的原则是：**第 1 波只做整合、性能和接入，不开始新的方法卡。**
T29–T35、T39、T42a/b、T45 等方法卡推迟到第 1 波合并之后。

## 追加的通用规则

- **G16 性能声明。** 任何性能改动都要提交可复现的基准脚本（放在 `benchmarks/efficiency/`），
  并在同一台机器上给出改动前后的原始数字、硬件、线程数和编译器版本。
  不同机器上的数字不能相互比较。基准结果写进验证记录，不只写在 PR 描述里。
- **G17 随机流是数值契约。** 改变随机数算法、抽样顺序或噪声消耗方式，等同于改变数值契约：
  新算法必须带版本号并写入 run identity；旧运行继续使用旧随机流并能逐位续算；
  两条路径都要有测试。默认值是否切换由维护者决定，agent 只提供可选开关。
- **G18 注册表（T47 合并后生效）。** 新增的 task、method、热浴、引擎或输入组合，
  必须在 `src/pyrpmd/registry.py` 中登记能力和成熟度；未登记的分派会使注册表一致性测试失败。
- **G19 不用 mock 掩盖真实路径。** 端到端测试必须走真实的输入解析和工作流分派；
  mock 只能替代外部程序或硬件。卡片要求在示例输入上运行而实际失败时（例如第四轮 T31 的
  `WKB action quadrature did not converge`），停下来报告原因，不要用 mock 让测试通过。

## 依赖与冲突

```text
第 1 波（彼此并行）:  T47   T48   T49   T52   T28(+extras)   T26(重做)   T36(重做)
                         │     │     │             │              │
第 2 波:                 │    T51    ├─> T27(重做)  └─> T50         ├─> T42a / T42b / T45（第 3 波）
                         │           └─> T16b(续) ──> T43（需 GPU）│
                         └──────────(T26 的组合白名单并入注册表，见 T47)
```

- **`native/thermal.*`、`native_ensemble.py`：** 本轮由 T49 独占；T16b（续）在 T49 合并后开始。
- **`native/philox.h`：** 由 T49 新建并独占；T27 只能包含使用，不能修改。
- **`propagation.py`、`block_propagation.py`：** T49 只改回滚快照路径；T26 如需改动，写进“需要协调”。
- **`dynamics.py`：** T49 只追加两个私有方法（回滚令牌的生成与恢复）；结构性钩子仍归 T26。
- **MetaD/OPES 模块：** T48 独占；T51 在 T48 合并后开始，T38 的分布式模块随 T48 一起整理。
- **`cli.py`：** T47 独占 `info` 分支；T52 追加 `import-rpmdrate` 子命令；T16b（续）追加 `migrate`。
  这些都属于追加式冲突。
- **`potentials/base.py`：** T28 增补只追加 `PESResult.extras` 可选字段；不改变已有字段和校验。
- **注册表与 T26：** T26 的组合白名单先写成独立的数据结构；T47 合并后迁入注册表。
  两者谁后合并，谁负责迁移。

## 不分派给 agent 的事项（维护者）

以下事项决定 PyRPMD 能否被视为同类程序中的首选，但需要维护者的凭据、计算资源或判断：

1. **旗舰算例达到发表级收敛。** 优先 H + H₂（P128 已接近，剩余父链半数等价与 P256 动力学收敛），
   其次 H + CH₄ 和 q-TIP4P/F 量子扩散。i-PI、RPMDrate、Caracal 的可信度都建立在这类复现之上。
2. **发布到 PyPI 与 conda-forge。** 构建与校验自动化已经存在（`docs/distribution.md`），
   只差项目所有权、可信发布者与审核。
3. **软件论文。** i-PI、RPMDrate、Caracal、NQCDynamics.jl 都有对应的论文。
4. **0.3 整合版本。** 建议在第 1、2 波合并且旗舰算例至少完成一个之后发布，
   发布说明以“整合与性能”为主题，而不是新方法数量。
5. **T49、T51 的默认值切换。** 计数器 RNG 和 OPES 压缩在本轮只作为可选开关；是否成为新运行的默认值，
   由维护者在看到验证记录后决定。
